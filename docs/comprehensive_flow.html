5.2.2 Lamaran — State Machine & Pipeline

stateDiagram-v2
    [*] --> diajukan : Perawat Apply
    diajukan --> diproses : Mitra Process (Lock)
    diajukan --> ditolak : Mitra Reject
    diproses --> diterima : Mitra Hire
    diproses --> ditolak : Mitra Reject
    diterima --> [*]
    ditolak --> [*]
    diajukan --> dibatalkan : Perawat Cancel
    diproses --> dibatalkan : Perawat Cancel
    dibatalkan --> [*]
⚠️ Anti-Poaching Mechanism
Kandidat yang sedang LOCKED atau HIRED oleh mitra lain TIDAK bisa diproses. Sistem return HTTP 409 Conflict.
Pipeline Flow: Lock, Hire & Reject
sequenceDiagram
    actor Mitra
    participant LC as LamaranController
    participant DB as Database
    participant RS as RiwayatPekerjaanService
    participant PS as PerawatStatusService
    
    Note over Mitra,PS: === PROSES (Lock) ===
    Mitra->>LC: POST /mitra/lamaran/process
    LC->>DB: Lock lamaran FOR UPDATE
    LC->>LC: Check: tidak final? tidak locked oleh mitra lain?
    LC->>DB: Create/Update Rekrutmen (status=LOCKED)
    LC->>DB: Update Lamaran (status=DIPROSES)
    LC->>DB: AuditLog (lamaran.lock)
    LC-->>Mitra: "Lamaran dikunci dan ditandai diproses"
    
    Note over Mitra,PS: === HIRE ===
    Mitra->>LC: POST /mitra/lamaran/hire
    LC->>DB: Lock lamaran FOR UPDATE
    LC->>DB: Create/Update Rekrutmen (status=HIRED)
    LC->>DB: Update Lamaran (status=DITERIMA)
    LC->>RS: startEmployment() → auto-create RiwayatPekerjaan
    LC->>PS: refresh() → update status ketenagakerjaan
    LC-->>Mitra: "Lamaran diterima dan kandidat di-hire"
    
    Note over Mitra,PS: === REJECT ===
    Mitra->>LC: POST /mitra/lamaran/reject
    LC->>DB: Update Rekrutmen (status=RELEASED)
    LC->>DB: Update Lamaran (status=DITOLAK)
    LC->>PS: refresh() → update status ketenagakerjaan
    LC-->>Mitra: "Lamaran ditolak"

9 Webhook System

9.1 Webhook Delivery Flow

sequenceDiagram
    participant Model as Eloquent Model
    participant Observer as VerifiedStatusWebhookObserver
    participant Service as OutgoingWebhookService
    participant Job as DeliverWebhookJob
    participant Endpoint as External Webhook URL
    
    Model->>Observer: updated() event
    Observer->>Observer: Check if status changed to "verified"
    Observer->>Service: dispatch(event, payload)
    Service->>Service: Find matching WebhookSubscriptions
    Service->>Job: Queue DeliverWebhookJob per subscription
    Job->>Endpoint: POST with signed payload
    Job->>Job: Record WebhookDelivery result
    
    alt Delivery Failed
        Job->>Job: Retry with exponential backoff
    end

14 Identity Model (perawat_nik)

🔑 Penting: Foreign Key Utama
Seluruh data portfolio perawat dihubungkan melalui perawat_nik (NIK 16 digit) sebagai foreign key, BUKAN perawat_id. Ini memungkinkan data tetap terintegrasi meskipun record perawat dibuat secara terpisah oleh berbagai pihak (kampus, lembaga, regulator, mitra).
